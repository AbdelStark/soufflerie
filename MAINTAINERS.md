## Decision process

Changes are proposed through issues and pull requests against the public
specification. The active maintainer reviews scope, technical evidence,
security, licensing, and compatibility and has final merge and release
responsibility. Material behavior changes require their owning specification or
RFC to change with the implementation. Disagreement should be recorded in the
pull request so the decision and tradeoff remain auditable.

Repository ownership rules live in [`.github/CODEOWNERS`](.github/CODEOWNERS).
They request review; they do not bypass branch protection or acceptance gates.

## Adding or removing maintainers

A maintainer change requires a pull request updating this file and CODEOWNERS,
with an explicit statement from the affected person. A prospective maintainer
should have sustained, constructive contributions and demonstrated care for the
project's numerical evidence and security boundaries. If no active maintainer
is available, the repository is unmaintained; no support or response-time claim
should be inferred.
