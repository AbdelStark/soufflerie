# Leased sweep lifecycle

`soufflerie.datagen.LocalSweepStateStore` is the reference compare-before-write adapter for
RFC-0005. It stores one bounded JSON state per expected case beneath
`sweeps/<sweep_digest>/state/`; callers never use directory listing to decide sweep membership.
The remote adapter introduced with fan-out must preserve the same transition and fencing
semantics.

## State and lease invariants

Every `CaseState` has an explicit schema version, full `sweep_digest`, `case_id`, four-state value,
monotonic `revision`, bounded attempt number, last/current `attempt_id`, and timezone-aware
`updated_at`. The sweep digest is rechecked against the containing store, so moving an otherwise
valid state file between sweep roots fails closed. The remaining fields are state-specific:

| State | Required evidence | Forbidden evidence |
|---|---|---|
| `pending` at attempt 0 | no attempt evidence | lease, result, error |
| retryable `pending` | prior attempt ID and error code; attempt below 3 | lease, result |
| `running` | attempt ID, owner, expiry strictly after update time | result, error |
| `succeeded` | attempt ID and full 64-character run digest | lease, error |
| `failed` | attempt ID and stable error code | lease, result |

An attempt ID is a random lowercase token generated by the orchestrator and passed unchanged to
claim, artifact publication, renewal, and completion. It is an execution fence, never dataset
identity. Repeating the same live claim with the same owner is a no-op. Reusing an expired token
or presenting its token under another owner fails closed.

## Legal transitions

```text
pending --claim--> running --verified success--> succeeded
                      |
                      +--retryable failure, attempts remain--> pending
                      +--deterministic/exhausted failure-----> failed
                      +--expired lease, attempts remain------> pending
                      +--expired third lease-----------------> failed
```

Leases last exactly ten minutes and can be renewed only by the current owner/token before expiry.
Expiry is reclaimable at the deadline, not after an additional grace period. The attempt count is
incremented only by claims and never exceeds three. Capacity and remote-execution errors retry
only when their typed exception instance is retryable; configuration, domain, numerical,
convergence, schema, integrity, validation, dependency, device, and invariant failures never
retry unchanged even if a caller attempts to override their retry flag.

`succeeded` is immutable. Completion first resolves and fully re-verifies the deterministic run
root through `RunArtifactStore.verify_run`. A later matching full digest is a verified no-op; a
different digest raises `ArtifactIntegrityError` as evidence of nondeterminism.

## Local compare-before-write

The local adapter validates the sweep/case/attempt/owner identifiers before deriving paths. Fixed
store components must be real directories, and case locks must be regular non-symlink files. A
per-case advisory lock serializes read/transition/write across processes. Each new JSON revision
is written to a same-directory temporary file, flushed and fsynced, then atomically replaces the
prior state and fsyncs the state directory. A crash before replace leaves the old revision; a
crash after replace leaves the complete new revision. The 64 KiB state cap applies before parsing
or publication.

The `revision` field supports the same compare-before-write behavior in a remote adapter with a
generation or ETag precondition. Local advisory lock files are coordination internals and are not
sweep evidence.

## Resume contract

`build_resume_plan` accepts the exact expected case IDs from the frozen design; it does not scan
the artifact root. It reaps expired leases, partitions pending/running/failed cases, and calls
`verify_run` for every successful digest before that case enters `succeeded_runs`. Missing,
truncated, oversized, schema-invalid, or digest-mismatched run content aborts resume instead of
silently resubmitting or skipping the case. Only `claimable_case_ids` may be submitted; active and
terminal cases remain excluded, and the intended design count is never reduced.

Run the focused transition and resume acceptance suite with:

```bash
uv run pytest tests/datagen/test_sweep_state.py tests/datagen/test_resume.py
```
