# HTTP API

Soufflerie exposes one closed schema-version-1 HTTP boundary. The checked
[OpenAPI document](../schemas/v1/openapi.json) is authoritative for paths,
fields, response codes, and component schemas. Unknown request fields, numeric
booleans, non-finite numbers, and values outside the supported design domain are
rejected before model or solver work.

## Endpoints

| Method | Path | Success contract | Purpose |
| --- | --- | --- | --- |
| `POST` | `/predict` | `200 PredictionResponse` | Synchronous surrogate prediction |
| `POST` | `/solve` | `202 SolveAccepted` | Admit one asynchronous solver reference |
| `GET` | `/solve/{job_id}` | `200 SolveStatus` | Poll retained job state |
| `GET` | `/solve/{job_id}/events` | `200 text/event-stream` | Replay ordered `SolveEvent` data |
| `GET` | `/health` | `200 HealthResponse` | Liveness and allowlisted readiness identity |
| `GET` | `/openapi.json` | `200 OpenAPI 3.1` | Machine-readable public contract |

The prediction and solve request body is:

```json
{
  "schema_version": 1,
  "shape": {
    "aspect_ratio": 0.75,
    "rotation_deg": 12.0,
    "scale": 1.0
  },
  "reynolds": 100.0
}
```

`aspect_ratio` is in `[0.5, 1.0]`, `rotation_deg` in `[0, 30]`, `scale`
in `[0.75, 1.25]`, and `reynolds` in `[40, 300]`. POST bodies must use
`application/json` and are limited to 16 KiB, including streamed bodies without
a `Content-Length` header. Repeated or invalid framing metadata fails closed.

The contract-only application implemented in issue #32 deliberately has no
model or solve adapter: valid calls return `503 DEPENDENCY_UNAVAILABLE` until
the prediction and job-lifecycle implementations supply those adapters. It does
not fabricate a successful response.

## Errors and correlation

Every HTTP response carries an `X-Correlation-ID` generated by the server.
Errors use one closed envelope and never copy untrusted values, exception text,
stack traces, hostnames, accounts, paths, or credentials into the body:

```json
{
  "schema_version": 1,
  "error": {
    "code": "CASE_OUT_OF_DOMAIN",
    "message": "request is outside the supported domain",
    "retryable": false,
    "correlation_id": "0199a1b2-c3d4-7e5f-8a9b-0123456789ab"
  }
}
```

| Status | Stable class |
| ---: | --- |
| `413` | `REQUEST_TOO_LARGE` |
| `415` | `UNSUPPORTED_MEDIA_TYPE` |
| `422` | `REQUEST_INVALID`, `CASE_OUT_OF_DOMAIN`, or `SCHEMA_UNSUPPORTED` |
| `404` | `JOB_NOT_FOUND` for a missing/expired job; `NOT_FOUND` for a route |
| `503` | integrity, device, dependency, capacity, or remote availability |
| `500` | generic internal failure |

## Readiness semantics

Health exposes exactly the package version, configured model/dataset/report IDs,
validation status, device class, liveness, readiness, and last successful check.
It excludes failure detail and infrastructure identity. Readiness is `ready`
only when the loaded model, model parent dataset, validation report, selected
report model, and report dataset all match the configured IDs; model/report
integrity, device availability, and warmup must also pass.

A red validation status alone remains ready. It is returned by health and every
future prediction response so clients cannot mistake service availability for
release approval. The canonical demo config binds red report
`4995ef8f8456030f467d`, model `7b6fd39c0ec78f452163`, and dataset
`4aefbbe88a18d233249b`.

## Contract verification

Regenerate the golden OpenAPI document together with all other versioned
schemas, then verify the complete checked set:

```bash
uv run python scripts/export_schemas.py
uv run python scripts/validate_schemas.py
uv run pytest tests/service/test_schemas.py tests/service/test_health.py tests/service/test_openapi.py
```
